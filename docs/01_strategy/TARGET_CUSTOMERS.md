## 2. 需求方客户画像

### C1 海外 AI 创业公司（P1）

| 项 | 内容 |
|----|------|
| 画像 | 种子轮至 B 轮，5–80 人，有模型训练或推理需求，自身无基础设施团队；常见于北美、欧洲、东南亚、中东 |
| 需求信号 | 公开招聘 infra/MLOps 岗位；公开讨论 GPU 短缺；产品发布导致用量激增；融资新闻后扩产 |
| 决策人岗位 | CTO / 联合创始人 / Head of Infrastructure / VP Engineering |
| 进入难度 | 中：决策链短，但对服务商信任门槛高、预算敏感 |
| 我方切入点 | 先做小范围需求分析或单点核验，用低门槛交付建立信任 |
| 不做的情形 | 要求「先给免费方案再谈」且无决策人；要求代垫费用；要求规避管制 |

### C2 模型训练公司（P1）

| 项 | 内容 |
|----|------|
| 画像 | 做大模型/垂类模型训练，需要大规模集群（数十至数百卡），对卡型、互联、机房位置敏感 |
| 需求信号 | 融资/发布会前的算力储备；集群扩容；训练任务公开排期；与云厂商合作公告 |
| 决策人岗位 | CEO / CTO / 训练负责人 / 采购负责人 |
| 进入难度 | 高：单笔金额大、技术尽调深、通常已有稳定供应商 |
| 我方切入点 | 不做「替代现有供应商」，做「第二供应商储备 + 跨境合规核验」 |
| 不做的情形 | 要求承诺特定先进卡型长期供应；要求代采受限芯片；要求我方承担履约担保 |

### C3 推理服务商（P1）

| 项 | 内容 |
|----|------|
| 画像 | 提供模型推理 API 或托管服务，追求单位成本与区域覆盖；对时延、带宽、稳定性敏感 |
| 需求信号 | 用户量增长、区域扩张、价格战压力、公开的节点扩容计划 |
| 决策人岗位 | COO / CTO / 基础设施负责人 |
| 进入难度 | 中：需求可计量、决策相对快，但毛利薄、对价格极敏感 |
| 我方切入点 | 多区域供给比较 + 持续采购管理；强调「不被单一供应商锁定」 |
| 不做的情形 | 只比价格、拒绝披露基本需求参数；要求我方承诺低于市场的价格 |

### C4 视频生成 / 3D AI（P2）

| 项 | 内容 |
|----|------|
| 画像 | 生成式视频、3D 资产、渲染类 AI 公司，突发性算力需求明显，训练与推理混合 |
| 需求信号 | 产品爆款后的排队/限流公告；融资；模型版本迭代节奏加快 |
| 决策人岗位 | CTO / 工程负责人 |
| 进入难度 | 中：需求波动大，预算季节性明显 |
| 我方切入点 | 弹性容量方案比较与短周期寻源 |
| 不做的情形 | 需求极不稳定且拒绝任何最低承诺；要求按小时零售价对标 |

### C5 机器人 / 仿真（P2）

| 项 | 内容 |
|----|------|
| 画像 | 具身智能、自动驾驶仿真、工业仿真，训练数据量大、仿真任务可并行 |
| 需求信号 | 融资、量产计划、仿真平台扩容、数据集发布 |
| 决策人岗位 | CTO / 仿真平台负责人 |
| 进入难度 | 中高：技术门槛高、验证周期长 |
| 我方切入点 | 长周期容量规划与多供应商组合建议 |
| 不做的情形 | 要求参与其核心数据处理的合规责任；数据出境路径不明时 |

### C6 AI 基础设施商（MaaS / 平台）（P2）

| 项 | 内容 |
|----|------|
| 画像 | 提供模型聚合、MaaS、Agent 平台，自身无重资产算力，需要稳定上游 |
| 需求信号 | 模型数量扩张、价格战、节点公告 |
| 决策人岗位 | CEO / COO / 供应链负责人 |
| 进入难度 | 高：对方自身即中介，容易把我方视为竞争者或可替代 |
| 我方切入点 | 作为其上游核验与寻源的外包方，而非与其争客户 |
| 不做的情形 | 要求我方交出需求方名单；要求独家；要求代持其客户资金 |

### C7 区域主权 AI 项目（P3）

| 项 | 内容 |
|----|------|
| 画像 | 国家/地区级 AI 基础设施计划，涉及政府采购、主权数据、本地化要求 |
| 需求信号 | 政府公告、招标、国家级 AI 战略发布 |
| 决策人岗位 | 主管部门、国有平台公司、总包集成商 |
| 进入难度 | 很高：资质、政治与合规门槛，周期长 |
| 我方切入点 | 本期只做研究与观察，不投入商务资源；不具备投标资质前不接触 |
| 不做的情形 | 涉及政府背书表述；要求承诺本地化落地能力；无资质参与投标 |

## 4. 客户优先级矩阵（评分法）

| 支付能力与意愿 | 20% | 预算量级与对服务费的接受度 |
| 合规可行性 | 20% | 是否触碰出口管制/数据出境红线 |
| 我方匹配度 | 15% | 现有供给/研究能否对接 |

**首选试点判断**：C3（推理服务商）与 C8（中国供给方）组合最适合做「首单结构」——需求可计量、周期短、合规压力相对可控。C2（大训练单）金额最大但合规与交付风险也最大，不宜作第一单。

## 5. 明确不做的客户类型

| 不做类型 | 原因 |
|----------|------|
| 要求规避出口管制的客户 | 触碰红线，且法律风险不可承受 |
| 要求代持/代收客户资金的客户 | 无牌照、无能力、无主体 |
| 要求我方承诺采购量或包销的供给方 | 轻资产模式不承担库存风险 |
| 要求独家代理但无对等承诺的渠道 | 单方面锁定资源 |
| 来源不明、拒绝披露基本用途的买方 | 可能涉及灰产或管制绕行 |
| 要求代签合同、代开发票、过账的客户 | 法律与税务风险 |
| 只比价、拒绝任何服务费、要求「免费找」的客户 | 单位经济不成立 |
| 涉及未获授权芯片或算力交易的任何一方 | 红线 |
| 要求我方出具「合规证明」的客户 | 不提供法律意见 |
| 政府/主权项目中要求我方承诺本地落地能力而我方无资质的 | 不可承诺 |

## 6. 客户获取原则

1. **外联权只在 CEO**。任何 AI Agent 不得发送邮件、私信、拨号（`PROJECT_BRIEF.md` 第 6 节）。
2. 线索必须按分级标注：公开线索 → 推断需求 → 潜在机会 → 已核实需求 → 已合格商机，禁止跳级。
3. 单条线索必须有来源、时间、信任度；无来源不入池。
4. 同一客户不得由多渠道同时接触，避免撞单（撞单规则见 `DEAL_PIPELINE.md`）。
