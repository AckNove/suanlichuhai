## 1. 商业模式一句话

**以双边服务费为收入来源、以研究核验与匹配解释为交付物、以证据链与流程为资产、以 AI 为产能**的跨境算力专业服务模式。我不持有算力，不承担库存与资金风险，收入来自「帮对方降低试错成本」这一件事是否被认可。

## 2. 商业模式画布（九宫格展开）

### 2.1 客户细分（Customer Segments）

| 客户群 | 角色 | 说明 | 优先级 |
|--------|------|------|--------|
| 中国智算中心 / GPU 云 / 算力运营商 | 供给方付费客户 | 有可售容量，缺海外客户与跨文化商务能力 | P1 |
| 海外 AI 创业公司 / 模型训练公司 | 需求方付费客户 | 需要特定卡型、地点、时限的容量 | P1 |
| 推理服务商 / 视频生成 / 3D AI / 机器人仿真 | 需求方付费客户 | 需求可计量、周期相对短 | P1–P2 |
| 区域主权 AI 项目 / 区域云 | 需求方付费客户 | 决策链长、合规敏感 | P2 |
| 全球算力供应商（中国以外） | C 线供给方 | 为 C 线全球寻源储备 | P3 |
| 渠道伙伴（顾问、律所、IDC 中介、云代理） | 引荐方 | 带来线索，按约定分配 | P2 |

### 2.2 价值主张（Value Propositions）

| 对象 | 价值主张 | 证据形态 |
|------|----------|----------|
| 需求方 | 用更少时间拿到「按规格筛过的可交付短名单」，并知道为什么配或不配、还要问什么 | 需求摘要 + 短名单 + 匹配理由 + 澄清清单 |
| 供给方 | 合格海外需求被介绍上门，不匹配的单提前被拿掉，规格差距被说清 | 需求画像 + 准入判断 + 商务准备包 |
| 渠道伙伴 | 线索被专业化处理，不被浪费、不被绕过 | 线索处理记录 + 分佣规则 |

### 2.3 渠道（Channels）

| 渠道 | 类型 | 现状 | 限制 |
|------|------|------|------|
| CEO 直接外联 | 主渠道 | 唯一被授权的外联方式 | 产能瓶颈在 CEO |
| 渠道伙伴引荐 | 辅渠道 | 未建立 | 无协议、无分佣规则 |
| 公开研究 + 内容 |  inbound 设想 | 无站点、无内容发布批准 | 对外材料须 CEO 批准 |
| 行业会议 / 交流会 | 线下 | 历史上参加过 1 次（2026-11-11） | 不产生持续线索 |

> **判断**：0→1 阶段渠道必须窄。宽渠道会制造「看起来有 pipeline、实际无人跟进」的假象。

### 2.4 客户关系（Customer Relationships）

- 需求方：项目制顾问关系，单项目周期内高频沟通，交付物书面化。
- 供给方：渠道合作关系，长期维护，按单结算。
- 关键原则：**不做自动群发、不做冷邮件轰炸**（既违规也损伤品牌）。

### 2.5 收入来源（Revenue Streams）

**6 类费用，全部灵活定价、逐案商议、CEO 审批，不设公开价目表。**

| 编号 | 费用类型 | 付费方 | 触发点 | 计费基础 | 适用场景 |
|------|----------|--------|--------|----------|----------|
| R1 | 客户采购顾问费 | 需求方 | 按月/按项目 | 项目工作量与服务范围 | 只出研究、短名单、方案比较，暂不牵线 |
| R2 | 供应商海外市场拓展服务费 | 供给方 | 按月/按阶段 | 服务周期与市场范围 | 帮供给方做海外市场研究与客户开发 |
| R3 | 项目寻源服务费 | 需求方或供给方 | 立项时 | 寻源范围与难度 | 特定规格的全球/跨境寻源 |
| R4 | 成功介绍费 | 通常为供给方 | 双方签约或首笔付款（以较早者为准） | 合同首年应付总额（个案约定） | 介绍后成交 |
| R5 | 交易协调费 | 委托方 | 交易推进关键节点 | 协调工作量与复杂度 | 合同谈判、交付协调、验收协调 |
| R6 | 长期采购管理费 | 需求方 | 按年/按季 | 管理规模与服务层级 | 持续采购、供应商绩效管理 |

**收费原则（必须遵守）**

1. **不写死费率**。历史 10%/8% 与 100 万美元门槛仅作「历史内部锚参考」，已被 CEO 2026-11-16 任务书取代为**逐案商议**，不得在系统、合同模板、话术中写成现行费率。
2. **首轮不报价**。对方追问或进入介绍协议阶段，才说明「成功后书面约定、个案商议」。
3. **双方都付费必须事前书面披露**，避免利益冲突（见 `COMMERCIAL_RISK_REGISTER.md` R-03）。
4. **不托管客户资金**，不在需方价格上加价。
5. 所有收费方案由 CEO 审批（见 `CEO_APPROVAL_MATRIX.md`）。

## 3. 双边平台 vs 单边服务：我们到底是什么

| 维度 | 双边平台（Marketplace） | 单边服务（Service Firm） | 我们（本期） |
|------|------------------------|--------------------------|--------------|
| 核心资产 | 流量与撮合量 | 专业能力与客户关系 | **专业能力 + 数据结构化** |
| 收费方式 | 抽成 / 订阅 | 顾问费 / 项目费 | **顾问费 + 成功费（逐案）** |
| 冷启动难点 | 鸡生蛋问题 | 信任与案例 | **信任与案例（同样难）** |
| 交付责任 | 平台不深度介入 | 深度介入 | **深度介入（研究、核验、协调）** |
| 合规责任 | 平台责任模糊 | 服务方责任清晰 | **清晰，且必须主动设边界** |

**结论（判断）**：本期是**单边服务公司**，不是平台。平台叙事会带来三个错误预期：客户以为「平台上有很多供给」、供给方以为「上架就有单」、内部以为「可以靠规则自动跑」。在无数据库、无案例、无主体的阶段，必须按服务公司的方式交付：一个个项目做，一份份交付物签收。

**未来演化条件**（不承诺）：当合格供给与合格需求各达到一定规模、匹配方法被反复验证、且有可签约主体后，才评估是否把重复部分产品化为平台。

## 4. 为什么供需双方愿意付费

### 4.1 供给方为什么付

| 痛点 | 我方提供的替代 | 付费逻辑 |
|------|----------------|----------|
| 海外客户触达能力弱（语言、时差、渠道） | 定向需求发现与初步接触准备 | 相当于外包 BD，但按结果付费 |
| 海外需求真假难辨，时间被浪费 | 资格筛查，不匹配的单提前拿掉 | 节省的是销售团队工时 |
| 规格说不清，报价对不上 | 需求澄清清单、双方规格对照 | 减少返工与丢单 |
| 不敢碰合规问题 | 合规筛查与律师转介（不提供法律意见） | 降低踩线风险 |

### 4.2 需求方为什么付

| 痛点 | 我方提供的替代 | 付费逻辑 |
|------|----------------|----------|
| 中国供给信息不透明，难以验证 | 结构化供给档案 + 核验记录 | 降低尽调成本 |
| 不知道哪家真能交付 | 可售 SKU、机房位置、交付周期核验 | 降低交付风险 |
| 合规与数据驻留不确定 | 风险提示与澄清清单 | 降低决策不确定性 |
| 采购过程无人持续管理 | 持续采购管理与方案比较 | 替代部分内部采购职能 |

### 4.3 付费意愿的真实约束（诚实写）

- 需求方可能认为「找供应商本来就免费」，因此 R1/R6 的付费意愿需要被验证，不能假设成立。
- 供给方可能只在**见到真实需求后**才愿意签介绍协议，因此「先协议后介绍」与「先介绍后补协议」的先后顺序须逐案处理。
- **双边都收费**会显著提高沟通成本，且必须披露；本期建议：**单一主付费方 + 另一侧免费或象征性收费**，具体由 CEO 逐案决定。

## 5. 从线索到回款的收入路径

```
线索入池
  → 研究建档（来源、时间、信任度）
    → 核验（供给：可售 SKU / 需求：规格·预算·时限）
      → 资格判定（是否 QUALIFIED）
        → 匹配（写清配/不配原因）
          → 商机立项（收费方案草案，CEO 审批）
            → 签署介绍协议或服务协议（律师稿）
              → CEO 介绍双方 / 交付服务
                → 双方直接签约（我方不代签）
                  → 触发条件达成（签约或首笔付款，以较早者为准）
                    → 开具账单 → 收款 → 复盘 → 脱敏案例入库
```

| 环节 | 我方动作 | 交付物 | 收入确认点 |
|------|----------|--------|------------|
| 研究 | 建档、核验 | 档案 + 证据链 | 无收入（成本） |
| 顾问服务 | 出短名单/报告 | 报告 + 澄清清单 | R1/R2/R3 可收 |
| 介绍 | 撮合介绍 | 一页对照 + 介绍记录 | 通常不单独收费 |
| 成交 | 双方签约 | — | R4 触发 |
| 协调 | 推进履约 | 会议纪要 + 问题清单 | R5 可收 |
| 长期管理 | 持续采购 | 季度报告 | R6 可收 |

**收入确认原则（待财务与律师确认）**：成功费在触发条件达成且可计量时确认；顾问费按交付里程碑确认；不预收大额、不做资金池。

## 7. 模式的三个内在张力

| 张力 | 表现 | 处理原则 |
|------|------|----------|
| 双边收费 vs 中立性 | 收两边钱会让双方怀疑「你到底替谁说话」 | 事前书面披露；优先单边主付费 |
| 轻资产 vs 可信度 | 无库存、无案例时，客户会问「你凭什么」 | 用可核验的交付物与流程证明，而不是用规模吹嘘 |
| 深度服务 vs 规模化 | 深度介入难以复制 | 先用 SOP + AI 降本，再谈规模化 |

## 8. 模式成立的前提条件（缺一不可）

1. CEO 可完成真实外联与谈判（产能是硬约束）。
2. 至少一条合格供给 + 一条合格需求能对上（当前为 0）。
3. 有可签约主体与可开票收款通道。
4. 有律师审过的介绍协议与数据合规意见。
5. 客户认可「服务费/成功费」而非「免费帮我找」。

> 前四条为**事实性缺口**，第五条为**待验证假设**。任何一条不成立，模式就只是纸面设计。
