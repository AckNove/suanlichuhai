# 客户采购需求采集表（20 问 + 评分与判定规则）

## 使用说明

- **时长**：首次沟通 30–45 分钟；允许客户分两次回答。
- **顺序**：先问工作负载与模型，再问规格、地点/合规、预算与决策；不要一上来问预算。
- **记录原则**：客户说什么记什么，不替客户补全；不确定的标 `待确认`。
- **不越权**：不报价、不承诺资源可得、不承诺交付时间、不评价客户现有供应商。
- **目标**：产出一份可用的《需求规格摘要》，并按规则判定线索等级。

## 填写栏位规范

每个问题固定记录四项：

| 栏位 | 填写规则 |
|---|---|
| 记录 | 客户原话要点；数字保留原始单位；不确定的地方写「不清楚」 |
| 状态 | `已确认` / `客户口述` / `待确认` / `不适用` |
| 来源 | 客户口述 / 客户书面材料 / 我方推断（推断必须标注） |
| 影响 | 对方案的影响：筛选条件 / 价格因素 / 合规门槛 / 无影响 |

## 「信息不足」判定规则

满足以下任一条件，判定为 `INSUFFICIENT_INFO`，不得进入方案阶段：

1. **必填五项缺失其一**：工作负载类型、卡型或可接受替代、GPU 数量（或量级）、使用时长/启动时间、预算量级（可给区间）。
2. **无决策路径**：无法确认决策人或决策流程，且客户拒绝说明。
3. **地点/合规未知且可能构成硬约束**：客户无法说明数据驻留或合规要求，而该要求可能直接排除大部分方案。
4. **完整度评分 < 12/20**。
5. **需求自相矛盾**：例如要求 64 卡 H100 单集群、两周内交付、预算显著低于市场常见水平，且客户不愿调整任一项。

判定后的处理：

| 判定 | 状态 | 动作 |
|---|---|---|
| 信息不足 | `INSUFFICIENT_INFO` | 发补充问题清单，约定 5 个工作日内补充；逾期归档 |
| 信息基本完整 | `NEEDS_VERIFICATION` | 进入寻源与供应商核验 |
| 完整且预算/时间/决策人均明确 | `VERIFIED` | 可准备方案对比，按内部流程报 CEO |
| 明确不匹配 | `NOT_MATCHED` | 书面说明原因，保留未来联系可能 |
