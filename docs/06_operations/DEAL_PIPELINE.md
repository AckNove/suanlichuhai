# 商机漏斗 · 阶段定义与流转规则

> 版本：v1.0　｜　日期：2026-11-16　｜　状态：内部草案，待 CEO 审批
> 适用范围：需求侧与供给侧共用的状态机执行细则。与 `PROJECT_BRIEF.md` 第 8、9 节一致；与 `BUSINESS_OPERATING_MANUAL.md` 第 4 节 SOP 对应。
> 真实状态：已核验供给 0、已核验需求 0、介绍协议 0、成交 0。**所有转化率当前无历史数据，一律标注「待采集」**。

---

## 1. 阶段总览

### 1.1 需求（Demand）漏斗

```
LEAD → RESEARCHED → NEEDS_VERIFICATION → VERIFIED → QUALIFIED
     → MATCHED → COMMERCIAL → WON
                            ↘ LOST
异常态：INSUFFICIENT_INFO / PAUSED / EXPIRED / NOT_MATCHED / CEO_PENDING / REJECTED
```

### 1.2 供给（Supplier）漏斗

```
LEAD → RESEARCHED → NEEDS_VERIFICATION → VERIFIED → QUALIFIED → ACTIVE
异常态：INSUFFICIENT_INFO / PAUSED / EXPIRED / REJECTED / CEO_PENDING
```

### 1.3 阶段定义表

| 阶段 | 中文 | 定义 | 关键判定 |
|------|------|------|----------|
| LEAD | 线索 | 仅有公开信息或推荐，未做结构化 | 有来源即可入池 |
| RESEARCHED | 已研究 | 已完成公开信息结构化建档 | 字段达标、来源可溯 |
| NEEDS_VERIFICATION | 待核验 | 已列出待确认项，等待一手确认 | 问题清单可答 |
| VERIFIED | 已核实 | 关键字段经 CEO/授权人一手确认 | 至少：主体、规格/需求、意愿 |
| QUALIFIED | 已合格 | 满足合格标准且有推进路径 | 合格清单全部满足 |
| MATCHED | 已匹配 | 与另一侧合格对象形成可解释匹配 | 匹配理由书面化 |
| COMMERCIAL | 商务阶段 | 已进入协议/报价/条款讨论 | CEO 已批准方案 |
| WON | 成交 | 双方签约或首笔付款 | 以较早者为准 |
| LOST | 失单 | 明确不再推进 | 有归因记录 |

## 2. 逐阶段执行标准

### 2.1 LEAD（线索）

| 项 | 内容 |
|----|------|
| 进入标准 | 有可追溯来源（URL/会议/推荐人）；标明侧别（供/需） |
| 退出标准 | 完成结构化研究 → RESEARCHED；信息严重不足 → INSUFFICIENT_INFO |
| 负责人 | 研究岗（登记：商务运营岗） |
| 必填字段 | 名称、侧别、来源 URL、来源标题、发布时间（未知写「未标注」）、获取时间、信任度、初步判断 |
| 停留时限 | 10 个工作日（内部目标） |
| 转化率度量 | 线索 → RESEARCHED 比例；当前**待采集** |

### 2.2 RESEARCHED（已研究）

| 项 | 内容 |
|----|------|
| 进入标准 | 上一阶段完成 |
| 退出标准 | 形成待确认问题清单 → NEEDS_VERIFICATION |
| 负责人 | 研究岗 |
| 必填字段 | 业务描述、区域、规格/需求要点、公开信号、证据列表、缺口清单 |
| 停留时限 | 10 个工作日 |
| 转化率度量 | RESEARCHED → VERIFIED；当前**待采集** |

### 2.3 NEEDS_VERIFICATION（待核验）

| 项 | 内容 |
|----|------|
| 进入标准 | 问题清单已准备，且**确认为 CEO 可问、对方可答** |
| 退出标准 | CEO 完成一手确认 → VERIFIED；无法接触 → PAUSED；确认不实 → REJECTED |
| 负责人 | 核验岗（准备）+ CEO（执行） |
| 必填字段 | 问题清单（≤8 问）、优先级、预期答案类型、接触前置条件 |
| 停留时限 | 20 个工作日；超时转 PAUSED 并说明原因 |
| 转化率度量 | 问题清单 → 有效回答率；当前**待采集** |

> **禁止**：AI 不得代发问题清单、不得冒充身份接触；外联权只在 CEO。

### 2.4 VERIFIED（已核实）

| 项 | 内容 |
|----|------|
| 进入标准 | 关键字段获一手确认（供给：可售 SKU/数量、机房、交付周期、签约主体、出海意愿；需求：规格、时限、预算量级、数据驻留、决策人） |
| 退出标准 | 按合格标准判定 → QUALIFIED / NOT_QUALIFIED |
| 负责人 | 核验岗记录，CEO 签字确认 |
| 必填字段 | 核验项 × 结论表、访谈日期与形式、待确认余项、信息提供者角色 |
| 停留时限 | 10 个工作日 |
| 转化率度量 | VERIFIED → QUALIFIED；当前**待采集** |

### 2.5 QUALIFIED（已合格）

**合格供给最低标准**：可售卡型与数量（或可调度容量）；能训/能推；机房城市；网络与交付周期；有签约主体；愿意谈海外或跨境；同意「成功介绍由供给方付费」这一**方向**（具体数字进协议，不在首轮报）。

**合格需求最低标准**：卡型/用量或可换算容量；训练/推理；期望地点与网络；上架时限；预算量级；数据驻留要求；有决策人或明确转介路径。

| 项 | 内容 |
|----|------|
| 进入标准 | 上述标准全部满足 |
| 退出标准 | 完成匹配 → MATCHED；无匹配对象 → NOT_MATCHED |
| 负责人 | 研究岗 + 核验岗双签 |
| 必填字段 | 合格判定表、缺失项=无、证据链、优先级评分 |
| 停留时限 | 30 个工作日（无匹配则转 NOT_MATCHED 或维持待匹配池） |
| 转化率度量 | QUALIFIED → MATCHED；当前**待采集** |

### 2.6 MATCHED（已匹配）

| 项 | 内容 |
|----|------|
| 进入标准 | 规格无硬冲突（卡型、地点、时限、驻留）；双方愿意被介绍；合规无「明显不可做」 |
| 退出标准 | 进入商务 → COMMERCIAL；不可推进 → NOT_MATCHED / PAUSED |
| 负责人 | 研究岗（匹配）+ AI 总负责人审 |
| 必填字段 | 匹配理由（配得上什么）、不匹配项（差在哪）、待澄清项、建议问法、合规标注 |
| 停留时限 | 15 个工作日 |
| 转化率度量 | MATCHED → COMMERCIAL；当前**待采集** |

> **强制要求**：匹配记录必须同时写「配得上」与「差在哪」。只写优点的匹配视为未完成。

### 2.7 COMMERCIAL（商务阶段）

| 项 | 内容 |
|----|------|
| 进入标准 | CEO 已批准商务方案；介绍协议覆盖该单（或同步签署）；双方同意被介绍 |
| 退出标准 | 签约/首笔付款 → WON；明确失败 → LOST |
| 负责人 | CEO（谈判）+ 商务运营岗（记录） |
| 必填字段 | 费用结构（逐案）、协议编号、介绍日期、对方决策链、关键条款、风险提示 |
| 停留时限 | 90 天（内部目标）；超时转 PAUSED 并复盘 |
| 转化率度量 | COMMERCIAL → WON；当前**待采集** |

### 2.8 WON / LOST

| 项 | WON | LOST |
|----|-----|------|
| 定义 | 双方签署正式合同，或发生首笔付款（以较早者为准） | 明确不再推进 |
| 必填字段 | 合同编号（敏感库）、金额区间（敏感库）、触发类型、收款计划 | 失单阶段、归因分类、可复用教训 |
| 负责人 | CEO | AI 总负责人 |
| 复盘 | 7 日内出复盘，沉淀脱敏案例 | 7 日内出归因，更新风险登记册 |

## 3. 异常态定义

| 异常态 | 触发条件 | 处理 | 可恢复 |
|--------|----------|------|--------|
| INSUFFICIENT_INFO | 公开信息严重不足，无法研究 | 保留在池，定期重扫 | 是 |
| PAUSED | 对方暂不回应、时机不对、内部资源不足 | 记录原因与唤醒条件 | 是 |
| EXPIRED | 超过时限且无进展（默认 LEAD 90 天） | 归档，可在有新增信号时重开 | 是（新建记录） |
| NOT_MATCHED | 合格但无匹配对象 | 留在匹配池，等待新对象 | 是 |
| CEO_PENDING | 等待 CEO 审批/决策 | 每日提醒，超过 5 个工作日升级 | 是 |
| REJECTED | 不合规、不真实、要求越界 | 永久关闭，记录原因 | 否（需 CEO 特批） |

## 4. 转化率度量方法（当前全部「待采集」）

| 指标 | 计算方式 | 当前值 | 采集开始条件 |
|------|----------|--------|--------------|
| 线索→研究完成率 | RESEARCHED+ / LEAD 总数 | 待采集 | 首次真实研究完成 |
| 研究→核验率 | NEEDS_VERIFICATION / RESEARCHED | 待采集 | CEO 开始外联后 |
| 核验成功率 | VERIFIED / NEEDS_VERIFICATION | 待采集 | 首次访谈后 |
| 合格率 | QUALIFIED / VERIFIED | 待采集 | 首次资格判定 |
| 匹配率 | MATCHED / QUALIFIED | 待采集 | 首批双向合格 |
| 商务转化率 | COMMERCIAL / MATCHED | 待采集 | 首份介绍协议 |
| 成交率 | WON / COMMERCIAL | 待采集 | 首单 |
| 平均周期 | 各阶段时间差 | 待采集 | 同上 |

**度量纪律**

1. 样本 <5 时只记录、不解读趋势，不写入对外材料。
2. 分母必须明确：按「条数」还是按「客户数」统计，两者不得混用。
3. 任何比率必须附时间窗（如「近 90 天」）。
4. 历史 10%/8% 不参与任何转化率计算。

## 5. 商机登记与保护规则

### 5.1 登记

| 规则 | 内容 |
|------|------|
| 唯一编号 | `DEM-YYYYMMDD-NNN` / `SUP-YYYYMMDD-NNN` / `DEAL-YYYYMMDD-NNN` |
| 登记时点 | 首次有实质推进意图时（进入 MATCHED 前后） |
| 登记内容 | 客户编号（脱敏）、来源、阶段、负责人、下一步、预计时间窗 |
| 重复检测 | 同主体多名称时以统一社会信用代码/官网域名为准去重 |

### 5.2 保护规则（渠道与内部）

| 规则 | 内容 |
|------|------|
| 线索保护期 | 登记后 90 天（假设，需协议确认）；期内同一客户的其他来源不重复计 |
| 归属判定 | 以**先登记且有实质跟进记录**为准；仅口头提及不计 |
| 撞单处理 | 发现重复立即停止接触，由 CEO 裁定归属 |
| 渠道分佣 | 须书面约定；无书面约定不产生分佣义务 |
| 保护期到期 | 无实质进展自动释放，可重新登记 |

> 说明：以上为内部规则设计，不构成对第三方的承诺；对外承诺须写入书面协议并经 CEO 批准。

### 5.3 禁止行为

- 抢注他人已登记的客户以获取归属。
- 用公开渠道批量抓取联系人后集中「占位」。
- 把未核实线索标为 QUALIFIED 以进入漏斗统计。

## 6. 预测方法（本期简化）

| 层级 | 方法 | 说明 | 可信度 |
|------|------|------|--------|
| L1 数量预测 | 各阶段存量 × 历史转化率 | **当前无历史转化率，不可用** | 不可用 |
| L2 加权预测 | 阶段权重法（LEAD 5%、RESEARCHED 10%、VERIFIED 25%、QUALIFIED 40%、MATCHED 60%、COMMERCIAL 80%） | 权重为**假设**，首单后校准 | 低 |
| L3 自下而上 | 逐单判断：对方是否有预算、时间窗、决策人、协议覆盖 | 依赖 CEO 判断 | 中（未来） |

**本期结论**：在首个成交出现前，**不做金额预测**，只做「阶段存量与卡点」管理。任何向 CEO 提交的预测必须标注「基于假设权重，不可用于融资或对外」。

## 附录 D　商机保护与撞单判定细则

| 情形 | 判定 | 处理 |
|------|------|------|
| 同一需求被两人先后登记 | 先登记且 7 天内有实质跟进者优先 | 后登记人转为协助角色 |
| 同一客户不同业务线 | 视为不同商机，可分别保护 | 需在登记时注明业务线 |
| 渠道伙伴与直客登记同一需求 | 以最终客户确认为准 | 渠道需提供客户授权或引荐记录 |
| 供应商已直接接触该客户 | 不构成我方保护 | 如实告知客户，避免误认代理关系 |
| 保护期内无任何实质推进 | 保护自动失效 | 90 天后释放（假设期限） |
| 客户明确要求更换对接人 | 以客户意愿优先 | 重新分配并记录原因 |
| 双方同时声称「已介绍」 | CEO 裁定，参考首次介绍时间与书面留痕 | 裁定结果入档，不得私下和解 |

**「实质跟进」定义（假设）**：至少完成一次与决策人的有效沟通，并在系统中记录下一步与日期。仅有「加了好友」「发过资料」不算。

**登记编号规则**：`DEM-YYYYMMDD-NNN`（需求）、`SUP-YYYYMMDD-NNN`（供给）、`DEAL-YYYYMMDD-NNN`（商机）；同日同序号递增，不得跳号或复用。
