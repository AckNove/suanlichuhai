## 0. 方法与评分说明

## 1. MATCH-R1-001：Lintasarta × 登甲智能

### 1.1 基本信息

| 项 | 内容 |
|---|---|
| 匹配编号 | MATCH-R1-001 |
| 需求方 | DEM-R1-004 Lintasarta（印尼雅加达，Indosat Ooredoo Hutchison 旗下） |
| 供给方 | SUP-R1-001 登甲智能（广州海珠琶洲） |
| 需求性质 | GPUaaS 运营商扩容（推断） |
| 供给形态 | GPU 卡时租赁 + Token 工厂 + 私有化部署 |
| 研究性粗评 | 62/100（定性粗评，非正式评分） |

### 1.2 匹配维度逐项对比

| 维度 | 需求方（Lintasarta，推断） | 供给方（登甲，公开自述） | 匹配判断 |
|---|---|---|---|
| GPU 型号 | 现有 8×H100 SXM/服务器，NVIDIA Sovereign AI Cloud | 「国产与主流多代际 GPU」，具体型号未公开 | **部分匹配/待核**：登甲是否可稳定提供 H100 级或等价卡未知 |
| 规模 | 首批规模未披露，扩容推断为数十至数百卡 | 单卡到千卡集群（自述） | **中**：规模能力理论上覆盖，但实际可售卡量未核 |
| 负载 | GPUaaS：训练 + 推理，政府/企业 | Token 推理 + 卡时租赁（训练/推理） | **高**：产品形态可直接对应 |
| 地点 | 印尼境内（数据驻留要求） | 广州 + 「多区域节点」（未公开具体位置） | **中**：地理近，但印尼本地节点未确认 |
| 网络 | 3.2Tbps InfiniBand，印尼境内低延迟 | 分布式存储 + 高速互联；出海页称 <200ms API | **中**：跨境延迟与带宽需实测 |
| 交付周期 | 未公开 | 1 小时起租；私有化最快 2 周；集群交付未公开 | **中高**：租赁交付快，但跨境设备/节点交付未核 |
| 价格机制 | 未公开 | 按需/包月/包年、按小时计费（无公开报价） | **待核**：双方价格均未公开，无法比较 |
| 数据驻留 | 印尼境内（主权 AI 要求） | Token 服务数据存储地未公开；私有化称数据不出域 | **风险**：若用境外 Token 服务，可能违反印尼数据要求 |
| 合规 | 印尼监管 + 美方出口管制外溢 | 需核出口管制筛查、最终用户审查 | **风险**：未核 |
| 合同主体 | Lintasarta / Indosat 集团 | 登甲（与腾讯云合作边界未明） | **待核** |

### 1.3 为什么匹配

1. **产品形态互补**：Lintasarta 已运营 GPUaaS（GPU Merdeka），需要持续补充 GPU 容量与推理能力；登甲同时提供卡时租赁、Token 服务与私有化部署，可覆盖「扩容 + 推理降本」两类需求。
2. **地缘与成本**：广州—雅加达距离近，运输/运维响应成本低；印尼市场对价格敏感，中国供应链的性价比具备理论优势。
3. **主权 AI 的「第二供应商」空间**：印尼强调 AI 主权但未排除中国技术；Lintasarta 现有栈为 NVIDIA，理论上仍需非美系备份或降本方案。
4. **供给方可核性相对最好**：登甲是三家供给候选中唯一有独立媒体证据（腾讯云合作）与清晰产品页的。

### 1.4 为什么不匹配（至少 2 条风险）

1. **印尼本地节点缺失**：Lintasarta 的核心卖点是「全部基础设施位于印尼、数据驻留印尼」；登甲公开信息中没有印尼节点，若以跨境方式供给，直接与需求方的主权 AI 定位冲突。
2. **NVIDIA 生态锁定与迁移成本**：Lintasarta 现有 8×H100 SXM + 3.2Tbps InfiniBand 栈；登甲的「国产+多代际」卡在互联、软件栈（CUDA 兼容）与性能上是否等价未核，迁移成本可能高于收益。
3. **供给能力未核**：登甲的卡型、卡量、机房位置、海外节点均为空白或自述；「70% 海外客户」无法验证。
4. **合规双重风险**：印尼侧的数据/安全审查 + 美方对中国 AI 芯片的出口管制外溢（含远程访问限制），需律师逐项确认。
5. **决策链不明**：Lintasarta 的 GPU 采购可能由 Indosat 集团统一决策，登甲方面也可能受腾讯云合作边界约束。

### 1.5 置信度：**中高**

说明：匹配的「逻辑置信度」较高（需求与供给形态对应清晰），但「事实置信度」中等（需求方扩容未证实、供给方能力未核）。综合定为中高，仅代表「值得继续核验」。

### 1.6 结论：**推荐推进（仅限内部核验，不对外）**

### 1.7 下一步动作

1. 补证：检索 Lintasarta/Indosat 2025–2026 年报、发布会、招聘中的 AI 基础设施扩容信息。
2. 核验登甲：是否有印尼/新加坡节点、可售卡型与卡量、跨境交付与数据驻留方案。
3. 形成「印尼本地推理节点 + 多代际 GPU」的方案假设（不含报价），交 CEO 决定是否经合规渠道接触。
4. 律师初筛：印尼数据驻留规则 + 美方出口管制对「第三国转售/远程访问」的适用性。

### 2.2 匹配维度逐项对比

| 地点 | 埃及（首个），可能扩展非洲 | 深圳河套（国内） | **低**：无海外节点 |
| 网络 | 跨境（非洲—中国） | 无公开跨境网络能力 | **低** |

| 数据驻留 | 埃及境内（官方明确） | 无海外数据驻留方案 | **冲突** |
| 合规 | NVIDIA 合作伙伴 + 非洲监管 + 西方融资结构 | 出口管制/数据出境未核 | **高风险** |

### 2.3 为什么匹配

1. **叙事契合**：Cassava 的「国家 AI factory + GPUaaS + 绿能」与天顿的「绿能智算全生命周期服务商」定位在概念上接近；非洲电力紧张使「绿能」成为差异化卖点。
2. **成本敏感**：非洲市场对资本开支敏感，中国设备/建设成本具备理论优势。
3. **上市公司背景**：天顿母公司 01396.HK 具备一定资本运作与项目融资能力，理论上可参与海外 AIDC 项目。
4. **异构调度**：若非洲项目需要混合算力（推理/政务/行业），量子湃的异构调度定位有想象空间。

### 2.4 为什么不匹配（至少 2 条风险）

1. **NVIDIA 绑定与合作伙伴身份**：Cassava 是非洲首家 NVIDIA 云合作伙伴，埃及项目明确使用 NVIDIA 加速计算；其技术栈、融资与伙伴结构大概率排斥中国算力设备。
2. **数据驻留冲突**：埃及项目要求数据驻留埃及，而天顿无公开海外节点、无跨境数据方案；以中国境内算力供给埃及政府/企业数据在合规上不可行。
3. **证据不足**：天顿仅有 1 条可核第三方来源（转载公告），官网不可读，卡型/卡量/海外能力全部空白；在此基础上的匹配属于「纸面推演」。
4. **地缘与融资约束**：项目涉及 Vodafone、NVIDIA 及可能的西方开发金融机构，中国供应商进入面临政治与采购规则障碍。
5. **交付与运维距离**：非洲项目的土建、电力、运维需要本地能力，天顿无公开海外交付记录。

### 2.5 置信度：**低**

### 2.6 结论：**待补充信息（不建议现阶段推进）**

### 2.7 下一步动作

1. 先补天顿证据：官网（换渲染方式/找镜像）、01396.HK 公告与年报、量子湃平台文档、客户案例。
2. 核验 Cassava：埃及项目采购主体、与 NVIDIA 协议性质、是否允许非 NVIDIA 卡、融资条款中的供应商限制。
3. 若两项都无法补证，**关闭该组合**，不投入商务资源。
4. 若天顿后续披露海外节点/海外客户，再重新评估（可考虑南非/肯尼亚节点，而非埃及首发）。

## 3. MATCH-R1-003：Sarvam AI × 硅基流动

### 3.1 基本信息

| 项 | 内容 |

| 匹配编号 | MATCH-R1-003 |
| 需求方 | DEM-R1-005 Sarvam AI（印度班加罗尔） |

| 需求性质 | 万亿参数模型训练 + 大规模多语言推理（推断） |
| 供给形态 | 词元平台 + 多芯片推理 + 专属实例 + 本地部署 |
| 研究性粗评 | 31/100（定性粗评，非正式评分） |

### 3.2 匹配维度逐项对比

| 维度 | 需求方（Sarvam，推断） | 供给方（硅基流动，公开） | 匹配判断 |
|---|---|---|---|
| GPU 型号 | NVIDIA（受投资方影响） | 适配 NVIDIA/AMD/昇腾/沐曦/摩尔线程 | **理论互补、实际低**：Sarvam 供应绑定 NVIDIA |
| 规模 | 万亿参数训练 → 万卡级（推断） | 平台方，非自有万卡集群 | **低**：训练侧无法承接 |
| 负载 | 训练 + 大规模多语言推理 | 推理为主（Token/专属实例） | **部分匹配**：仅推理侧 |
| 地点 | 印度境内 | 中国 + 国际站（节点未公开） | **低** |
| 网络 | 印度境内低延迟 | 跨境 token API | **低**：延迟与稳定性未核 |
| 交付周期 | 训练集群按年，推理可快速 | Token API 可快速开通；专属实例周期未公开 | **中** |
| 价格机制 | 未公开 | 平台有公开价目（不得作为报价引用） | **待核** |
| 数据驻留 | 印度境内（主权 AI 要求） | 数据路径未公开；跨境 Token 涉及出境 | **冲突** |
| 合规 | 印度对中资审查 + NVIDIA 投资条款 | 词元跨境合规未明（高风险） | **高风险** |
| 合同主体 | Sarvam 印度实体 | 硅基流动境内/国际站主体（未明） | **待核** |

### 3.3 为什么匹配

1. **推理侧技术互补**：Sarvam 需要面向 14 亿人的低成本多语言推理；硅基流动的多芯片适配与推理加速能力理论上可降低单位 token 成本。
2. **国产芯片叙事**：若印度未来允许非美系芯片用于非敏感推理，硅基流动的昇腾/沐曦/摩尔线程适配经验具备稀缺性。
3. **平台化交付**：Token API/专属实例的交付速度快于自建集群，适合模型公司的弹性推理需求。

### 3.4 为什么不匹配（至少 2 条风险）

1. **供应绑定**：Sarvam 获 NVIDIA 投资，且被 NVIDIA 定位为主权 AI 案例；其训练与推理大概率优先使用 NVIDIA 生态，切换动力不足。
2. **数据驻留与跨境冲突**：印度主权 AI 要求数据/模型在境内；硅基流动的 Token 服务涉及跨境数据流，合规上难以满足。
3. **印度对中资的审查**：印度对中国科技企业的投资、设备与服务审查趋严（具体规则需律师确认），整机/云服务进入门槛高。
4. **训练侧完全无法承接**：万亿参数训练需要万卡级集群与长期机房/电力，硅基流动是平台方而非算力持有方。
5. **硅基流动自身合规未明**：国际站运营主体、数据路径、词元跨境的合规定性均未公开。

### 3.5 置信度：**低**

### 3.6 结论：**不推荐（短期）**

本组合的价值不在于成交，而在于说明：**需求真实 ≠ 可匹配**。印度主权 AI 的算力需求巨大，但对中国供给方的合规壁垒最高，应作为「观察样本」而非「推进对象」。

### 3.7 下一步动作

1. 不投入商务资源；仅保留政策跟踪（印度 FDI/采购/数据规则变化）。
2. 若印度开放非敏感推理或 Sarvam 转向多芯片，再评估「第三国节点 + 本地部署」的变通方案。
3. 将本组合作为内部培训案例：如何在需求信号强时仍做出「不推荐」判断。

## 5. 结论与建议

1. 三组匹配中只有 **MATCH-R1-001** 值得投入下一轮核验资源；另外两组应「先补证/先观察」，不进入商务流程。
2. 匹配的最大瓶颈不在「需求是否存在」，而在**三件事**：①中国供应商的海外节点与数据驻留能力；②出口管制与第三国转售的合规路径；③供给方可核的真实卡量与交付能力。
3. 建议 CEO 本轮只做一个决定：**是否授权对 MATCH-R1-001 进行内部深度核验（不对外接触）**。其余两组暂不决策。
