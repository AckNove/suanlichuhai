## 2. 已锁定决策（以此为准，旧稿如冲突则作废）

以下均由 CEO 在 2026-11-12 至 2026-11-13 确认或要求，是后续执行的权威口径。

### 2.1 主业

- 主线：中国可交付**智算供给**对接海外或跨境需求。智算供给指能拿出来交付的计算能力，至少要说清：卡型与可上架数量、能训还是能推、机房位置与网络、交付周期与计费、数据驻留与合规边界。
- 词元 / 模型 API 只作**相邻撮合品类**，流程和收费逻辑可套用，标的改为调用量或年承诺额；跨境比交算力更敏感，须律师意见后才能作为可谈标的，不替代主线，也不作为第一笔费的默认标的。
- 不做：自营机房或 GPU 集群、自营 Token 工厂或模型 API 零售、芯片灰市或绕出口管制渠道、资金托管、在需方价格上加价。

### 2.2 收费（内部锚，2026-11-12 CEO 锁定）

- 成功介绍费由**供给方**支付；计费基数为合同**首年应付总额**。
- 分档下限：不满 100 万美元不低于 **10%**；满 100 万美元不低于 **8%**。可往上谈，不默认往下。
- 100 万美元是临时门槛，依据 2026-11-05 公开云价目（证据 B-E22 Runpod、B-E23 Lambda）估算的集群年包量级，**不是本项目成交价**；待自有成交后再校准。当时估算约 32 张 H100 或约 24 张 H200 的公开标价年包约等于 100 万美元；中国外送或包租价可能更低。
- 触发：双方签署正式合同，或发生首笔付款，以较早者为准。窗口：经我方介绍后 12 个月内成交均计入。
- 辅线：只出档案、匹配报告和澄清清单、暂不牵线，可收项目顾问费；日后谈成，顾问费可抵介绍费。
- 仍缺：介绍协议正式文本、收款主体。

### 2.3 对外怎么说（2026-11-13 CEO 明确，优先级高于此前所有对外草稿）

## 5. 赚钱链条：设计 vs 实际

设计中的链条：

获客（分边）→ 核实合格供给 / 合格需求 → 匹配并写清原因 → 与供给方签介绍协议 → CEO 介绍双方、双方直接签约 → 合同签署或首笔付款触发 → 向供给方按首年应付总额收 10% 或 8% → 复盘并校准门槛。

辅线：只出报告则收顾问费，日后可抵介绍费。

**实际位置：** 停在「公开线索建档 + 内部清单」。核实、协议、介绍、签约、账单、回款均未发生。一手成交访谈 = 0。

合格标准（经营框架第 3 节，摘要）：

- 合格供给：可售卡型与数量、训/推、机房城市、网络与交付周期、签约主体、愿意对接海外或跨境、同意「成功介绍由供给方付费」这一方向（数字进协议，不在首轮报）。
- 合格需求：卡型/用量、训/推、地点与网络、时限、预算量级、数据驻留、有决策人或明确转介路径。
- 公开海报和官网宣传不是合格供给；未谈过的媒体点名买家不是合格需求。

## 7. 建议其他助手重点审的问题

请给出可执行的反对或补强，不要只复述本文件。建议至少回答：

1. 主业是否应坚持「智算介绍对接」，还是应部分转向词元交易？若转向，如何避免与百度词元所及「词元中转站」同质，以及跨境合规如何处理？
2. 对外分边话术是否已经做到「不把赚钱结构直接说给客户」，同时又没有因过度谦虚（没有平台、没有案例）而无法开口？还需要改哪几句？
3. 10% / 8% 与 100 万美元临时门槛是否站得住？有无更好的内部锚，或不该在第一笔成交前把费率定得过死？
4. 经营框架里「先补合格需求，再拿已选供给去验证」的顺序是否对？若对，第一批需求应该从哪类对象、用什么不违规的方式准备（注意：外联仍只能由 CEO 发出）？
5. 在话术未批、主体和协议未定的前提下，交回执行时，最应该先做的三件准备是什么？哪些工作其实没有商业意义、应该停？
6. 介绍协议商业要点有无重大遗漏或对客户不可接受之处？（正式法律文本仍须律师，助手不得冒充法律意见。）

审阅结论请写清：建议保持的决策、建议修改的决策、建议立刻准备的动作、建议明确不要做的事。然后由 CEO 决定是否交回本助手执行。
