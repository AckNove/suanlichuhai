### 1.1 每份材料的核心内容与使用口径（内部）

| 材料 | 核心内容 | 使用口径（内部限制） |
|------|----------|----------------------|
| 01 公司介绍 | 定位、三条业务线、服务范围、主体状态说明 | 首次触达/会议后；不得出现费率、虚构案例、已合作表述 |
| 02 供应商合作介绍 | 为供应商带来的海外需求筛选、商机引入与渠道价值 | 供应商首次沟通；只讲对方获得什么，不承诺采购量或成交 |
| 03 客户服务介绍 | 需求分析→寻源→核验→比较→商务协调的服务流程 | 客户回信后；不承诺资源、交付时间、价格更低 |
| 04 首次联系话术 | 5 个场景×2 版话术＋禁用词 | 按场景取用，不混用；首轮不谈费率 |
| 05 供应商访谈表 | 30 问，覆盖资源、授权、容量、交付、价格、合规 | 首轮/二轮访谈；先资源与授权，再价格 |
| 06 客户需求采集表 | 20 问＋合格度评分 | 需求访谈；客户侧 12 问为最小集，20 问为完整集 |
| 07 公司一页纸 | 一页版定位与服务能力 | 会议现场、快速介绍；英文优先 |
| 08 采购方案样例 | 虚构的采购方案结构演示 | 仅演示方法论；必须显著标「样例/虚构」，不得改名冒用 |
| 09 供应商核验清单 | 25 项核验项与证据要求 | 内部为主；对外仅作流程说明，不替代核验结论 |
| 10 跟进模板 | 8 个场景的跟进邮件/消息模板 | 首访后 24h/72h/7d/30d 使用；每次给明确下一步 |

### 1.2 材料状态流转

`未落盘 → 草案 → 自检 → 待 CEO 批准 → 已批准（有编号）→ 已停用/已撤回`

- 只有「已批准」状态可外发；「待 CEO 批准」一律仅限内部使用。
- 状态变更须在材料台账与本索引同步登记；口头同意不改变状态。
- 已撤回材料不得继续使用，须回收或标注作废。

### 2.4 组合使用规则

1. 单次外发**最多 2 份附件**；超过须 CEO 单独批准。
2. 未获批前**只口头、不书面**；口头内容同样受红线约束。
3. 不把 A 场景材料用于 B 场景（如把客户服务介绍发给供应商）。
4. 样例材料（08）绝不与真实客户材料混装或作为附件转发。
5. 同一对象不同阶段的材料版本须一致，避免前后矛盾。
6. 材料更新后旧版本立即停用，并在跟进表/台账记录替换关系。

## 3. 外发前检查清单（逐项打勾，缺一不发）

**A. 授权与版本**
- [ ] 该材料在 CEO 批准清单内，且**有批准编号/日期**（口头同意不算）。
- [ ] 使用的是最新版本（版本号、日期与批准记录一致）。
- [ ] 发送对象、发送渠道、发送内容已记录在跟进表/CRM。

**B. 内容红线**
- [ ] 无任何具体费率、百分比、分档数字（10%/8% 等历史锚**绝不出现**）。
- [ ] 无「保证更便宜」「保证拿到卡」「保证合规」等承诺。
- [ ] 无虚构客户案例、合作背书、资质、奖项、联系人姓名与联系方式。
- [ ] 供应商/客户名称均标注「公开线索，未核实」或已取得对方书面同意。
- [ ] 公司主体表述为「主体设立中/待确认」，未暗示已可签约收款。
- [ ] 无未经授权的第三方商标、Logo、数据、图片。

**C. 语言与格式**
- [ ] 中英文版本内容一致（数字、免责声明、联系方式占位符均替换正确）。
- [ ] 占位符（姓名、邮箱、电话、公司名、日期）已全部替换或按需删除。
- [ ] 文件页眉/页脚含版本号与「草案」标识（对外版按 CEO 批准口径处理）。
- [ ] 排版无乱码、无内部批注、无修订痕迹、无隐藏表格列。

**D. 合规与数据**
- [ ] 不含客户/供应商敏感数据（价格底线、合同条款、个人信息）。
- [ ] 涉及跨境、数据驻留、出口管制的表述仅为「待核实/需专业意见」，未作结论。
- [ ] 附件不含内部文件（如本索引、定价框架、条款清单草稿）。

**E. 发送后**
- [ ] 在 `commercial_opportunities` / 跟进表记录发送时间、材料版本、批准编号。
- [ ] 保存发送副本（邮件/附件）备查。
- [ ] 对方有异议或要求修改时，停止发送新版本，先报 CEO。

**一票否决项**：无批准编号、含费率、含虚构案例、主体表述越界——任一项不通过即不得发送。

### 3.1 外发审批流程（五步）

| 步骤 | 责任人 | 产出 | 时限 |
|------|--------|------|------|
| 1 需求提出 | 商务负责人（经 CEO 授权） | 外发目的、对象、材料清单 | 发送前 2 个工作日 |
| 2 材料准备 | 商务/材料维护人 | 填空版本、占位符替换记录 | 同上 |
| 3 自检 | 非发送本人 | 第 3 节清单签字/日期 | 发送前 1 个工作日 |
| 4 CEO 批准 | CEO | 书面批准、编号 `SM-YYYYMMDD-NN` | 常规 2 个工作日；紧急当日 |
| 5 发送与登记 | 发送人 | 台账记录、发送副本 | 发送当日 |

## 4. 禁止事项

1. ❌ 未经 CEO 批准发送任何对外材料（含「先发看看反应」）。
2. ❌ 在材料中写入或口头补充具体费率、分成比例、最低收费。
3. ❌ 把 `08_sample_procurement_proposal` 的虚构样例当作真实案例展示或改名冒用。
4. ❌ 把「公开线索」写成「已合作」「已签约」「合作伙伴」。
5. ❌ 使用个人邮箱/个人微信/个人 LinkedIn 以外未经批准的渠道群发。
6. ❌ 在材料中承诺资源可用性、交付时间、合规合法性。
7. ❌ 附带内部文件（本索引、`docs/02_commercial/`、`docs/04_contracts/` 草稿）。
8. ❌ 使用未经授权的第三方 Logo、客户名、数据图表。
9. ❌ 一稿多发给互相竞争的供应商/客户而不做信息隔离。
10. ❌ 材料修改后不更新版本号、不通知 CEO 即继续使用旧批准编号。

### 4.1 常见错误与正确做法（假设场景，非真实事件）

| 假设场景 | 错误做法 | 正确做法 |
|----------|----------|----------|
| 客户要看案例 | 把 08 样例改名当真实项目 | 明确说「这是方法与结构样例，非真实项目」 |
| 供应商首轮追问费率 | 答「大概 10%」或「行业惯例」 | 只说「成功后按个案书面约定，首轮不报价」 |
| 内部汇报提及线索 | 写成「合作伙伴」「已建立合作」 | 写「公开线索，未核实，未接触」 |
| 想快速推进 | 用个人微信发未批准 PDF | 仅用获批版本与登记渠道，先走审批 |
| 中英文版本更新不同步 | 只改中文就发出 | 双语同步更新并重新批准后再发 |

## 5. 版本与批准管理

| 环节 | 规则 |
|------|------|
| 起草 | bilingual-kit 维护 `docs/03_sales/`；内容须与本索引及 `docs/02_commercial/` 手册一致 |
| 自检 | 按第 3 节清单逐项检查，记录检查人/日期 |
| 批准 | CEO 书面批准（邮件/批注均可，须可追溯）；批准编号格式建议 `SM-YYYYMMDD-NN` |
| 外发 | 仅使用获批版本；每次外发登记 |
| 变更 | 任何实质修改（费率、案例、主体表述、承诺）须重新批准；文字润色可不重批但须留痕 |
| 撤回 | 发现错误版本已外发：立即通知对方停用、发更正说明、报 CEO，并在跟进表记录 |

### 5.1 外发台账字段（建议）

| 字段 | 说明 |
|------|------|
| 台账编号 | `SM-YYYYMMDD-NN` |
| 发送日期 | 实际发送日 |
| 材料与版本 | 文件号＋版本号 |
| 批准编号 | CEO 批准记录编号 |
| 发送人/复核人 | 实名 |
| 对象 | 机构＋角色（不记录个人隐私） |
| 渠道 | 邮件/会议/平台私信等 |

| 对方反馈 | 摘要与日期 |
