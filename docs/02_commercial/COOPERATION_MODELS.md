# 合作模式（Cooperation Models）

> 项目：中国算力国际化项目（CCGS）· 中国算力出海
> 版本：v1.0 ｜ 日期：2026-11-16 ｜ 状态：内部草案，待 CEO 审批
> 性质声明：本文是商业合作模式设计，**不是法律文本、不构成法律意见**；任何模式落地前须由律师审核正式合同。所有对外表述、报价、签约须 CEO 批准。
> 依据：`docs/00_project_audit/PROJECT_BRIEF.md` §3–§6；历史参考 `业务模式-内部定稿.md`、`经营框架-开口到收款.md`（冲突以 BRIEF 为准）。
> 核心原则：**收费灵活、逐案商议、CEO 审批；不写死费率；不托管资金；不在需方价格上加价；双方付费必须事前书面披露。**

---

## 0. 五种模式总览

| 模式 | 一句话定位 | 主要付款方 | 收费类型（候选） | 典型场景 | 当前可用性 |
|------|------------|------------|------------------|----------|------------|
| **A. 客户采购顾问** | 帮需求方把「要买什么、向谁买、怎么买」说清楚 | 客户（需求方） | 顾问费（固定/阶段）＋可选成功费 | 客户有明确采购计划但缺算力专业能力 | 可设计，待 CEO 批准 |
| **B. 供应商非独家渠道合作** | 作为供应商的非独家海外渠道，持续带入合格需求 | 供应商（供给方） | 市场拓展服务费＋成功介绍费 | 供应商有稳定可售资源、想开发海外 | 可设计，待协议 |
| **C. 按商机登记的成功介绍** | 针对单笔可识别商机，介绍成交后收费 | 供应商（供给方，默认） | 成功介绍费 | 已有一组明确供需、可登记 | 可设计，待协议 |
| **D. 联合市场拓展** | 与伙伴（区域云/IDC/集成商/咨询方）共同拓客、共担投入 | 按项目约定（一方或双方） | 项目服务费/分成/各自承担 | 伙伴有本地客户资源、我方有中国供给 | 可设计，待伙伴确认 |
| **E. 长期算力采购管理** | 替客户持续管理多笔算力采购与供应商关系 | 客户（需求方） | 年度/季度管理费＋绩效费 | 客户多区域、多供应商、持续扩容 | 可设计，待 CEO 批准 |

**说明**：模式不是「收费套餐」，而是「谁付钱、买什么、什么时候触发」。同一客户/供应商在不同阶段可以切换模式（见第 7 节组合规则），但**同一笔交易不得重复收费**。

## 1. 模式 A：客户采购顾问（Customer Procurement Advisory）

> 定位：客户买的是「决策质量」——把需求规格、候选供给、交付风险、商务条款讲清楚，而不是替他买卡。

| 项目 | 设计 |
|------|------|
| **付款方** | 客户（需求方）。如后续由供应商支付成功费，须按第 8 节事前披露。 |
| **服务内容** | 需求梳理与规格定义；供给市场扫描；供应商初筛；方案对比（卡型/地点/交付/网络/价格机制）；风险清单；商务谈判支持；合同要点建议（非法律意见）。 |
| **交付物** | 《需求规格说明》《候选供给短名单（含核验状态）》《方案对比表》《风险与待澄清清单》《谈判要点》。 |
| **收费方式** | 固定顾问费（按项目/阶段）＋可选成功费；金额逐案商议，CEO 审批；不写死比例。 |
| **交易触发条件** | 顾问费：签约或阶段交付验收；成功费：客户与供应商合同签署或首笔付款（孰早）。 |
| **双方责任** | 我方：独立、勤勉、披露利益冲突、不虚构供给；客户：提供真实需求信息、按时反馈、指定决策人。 |
| **佣金结算** | 顾问费按里程碑开票；成功费在触发事件后按约定账期结算；币种与汇率见 `PRICING_AND_FEE_FRAMEWORK.md`。 |
| **客户保护** | 服务期内客户信息保密；不把客户需求转卖给其他供应商；不绕过客户直接与供应商签约。 |
| **非独家/独家** | 默认非独家；客户可要求特定区域/品类短期独家（需额外对价与 CEO 批准）。 |
| **利益冲突** | 若同时服务该客户的供应商，必须书面披露并取得客户同意；不得同时代表双方谈判同一笔交易。 |
| **风险** | 客户预算不足、决策链长、顾问费被压价；交付物被白嫖。 |
| **适用场景** | 客户首次采购中国/跨境算力；客户内部无算力采购专家；采购金额较大、需要独立比较。 |
| **不适用场景** | 客户只想要一份免费名单；客户要求我方承诺交付或合规；客户要求我方托管资金。 |

**关键条款**：范围与交付物清单、验收标准、固定费与成功费的抵免关系、保密、利益冲突披露、终止与未完成交付处理。落地模板见 `docs/04_contracts/PROCUREMENT_ADVISORY_TERM_SHEET.md`。

## 2. 模式 B：供应商非独家渠道合作（Supplier Non-exclusive Channel）

> 定位：供应商买的是「持续的、筛过的海外/跨境需求流」，不是一次性介绍。

| 项目 | 设计 |
|------|------|
| **付款方** | 供应商（供给方）。 |
| **服务内容** | 海外市场研究；目标客户画像；需求开发与筛选；商机登记与介绍；商务协调；月度/季度管道报告。 |
| **交付物** | 《目标市场与客户画像》《月度商机管道表》《合格需求说明》《介绍记录》《复盘报告》。 |
| **收费方式** | 市场拓展服务费（固定月费/阶段费）＋成交后的成功介绍费；分开计价，逐案商议。 |
| **交易触发条件** | 服务费：按月/阶段；成功费：该供应商与经登记客户的合同签署或首笔付款（孰早）。 |
| **双方责任** | 供应商：提供真实可售资源、及时报价、指定接口人、不绕过登记商机；我方：真实开发、不虚构需求、按登记机制保护商机。 |
| **佣金结算** | 成功费按登记商机逐笔结算；服务费按月/季开票；结算周期与账期写入协议。 |
| **客户保护** | 商机登记 + 保护期（默认 180 天，可续）；登记须书面确认；同一商机不向多家供应商重复兜售。 |
| **非独家/独家** | **默认非独家**；独家仅在特定品类/区域、有最低承诺量或保底费时考虑，须 CEO 批准。 |
| **利益冲突** | 若我方同时服务客户侧（模式 A/E），须披露；同一交易不得双边收费而不披露。 |
| **风险** | 供应商跳单、商机归属争议、服务费拖欠、供应商资源不实消耗我方信誉。 |
| **适用场景** | 供应商有稳定可售资源、内部海外销售能力弱、愿意接受非独家与成功付费方向。 |
| **不适用场景** | 供应商要求排他但无保底；供应商无稳定资源；供应商拒绝书面商机登记。 |

**关键条款**：非独家、商机登记与保护期、佣金基数与结算、品牌使用、客户归属、终止后存量商机处理。落地模板见 `docs/04_contracts/CHANNEL_PARTNERSHIP_TERM_SHEET.md`。

## 3. 模式 C：按商机登记的成功介绍（Registered Deal Introduction）

> 定位：最小可行模式。一笔可识别的商机、一次书面登记、一次介绍，成交后收费。

| 项目 | 设计 |
|------|------|
| **付款方** | 默认供应商（供给方）；如客户方也付费，须事前书面披露并经 CEO 批准。 |
| **服务内容** | 商机登记；供需双方资格核验；匹配说明（配/不配及原因）；介绍与引荐；交易协调；跟进记录。 |
| **交付物** | 《商机登记确认》《匹配说明》《介绍邮件/会议纪要》《成交与结算记录》。 |
| **收费方式** | 成功介绍费：按「首年合同应付总额」的一定比例或固定金额，逐案商议，CEO 审批；**不写死 10%/8%**。 |
| **交易触发条件** | 双方正式合同签署，或发生首笔付款，**以较早者为准**；介绍后 12 个月内成交可计入（窗口可选，协议写明）。 |
| **双方责任** | 供应商：按登记商机跟进、如实报价、不绕开我方与客户私下成交；我方：真实介绍、不夸大、不隐瞒冲突。 |
| **佣金结算** | 触发后开票；一次性或随供应商回款分期；账期、币种、汇率写入协议。 |
| **客户保护** | 登记即锁定归属；保护期内成交均计入；登记须双方书面确认。 |
| **非独家/独家** | 该商机内默认「单向保护」（供应商不得绕开我方），但不限制供应商与其他渠道合作。 |
| **利益冲突** | 若客户也向我方付费，必须披露；不得同时向供需双方收取未披露的费用。 |
| **风险** | 跳单（直接/间接）、客户被供应商直接接触后否认介绍、成交金额认定争议。 |
| **适用场景** | 已有一组较明确供需；供应商愿意签介绍协议；单笔金额可识别、可举证。 |
| **不适用场景** | 无法举证介绍行为；客户/供应商拒绝书面登记；交易结构复杂到无法认定成交额。 |

**关键条款**：定义（介绍/商机登记/成交/首年应付总额）、登记与保护、费用与支付、触发与窗口、反跳单、争议解决。落地模板见 `docs/04_contracts/INTRODUCTION_AGREEMENT_TERM_SHEET.md`。

## 4. 模式 D：联合市场拓展（Joint Go-to-Market）

> 定位：与有本地客户资源的伙伴（区域云、IDC、系统集成商、咨询公司、行业协会）共同开发市场，共担投入、共享成果。

| 项目 | 设计 |
|------|------|
| **付款方** | 按项目约定：可为我方付伙伴、伙伴付我方、双方各自承担、或从成交收入中分成。 |
| **服务内容** | 联合客户开发；联合方案与材料；联合拜访/活动；供需匹配；交易协调；分工与客户归属管理。 |
| **交付物** | 《联合市场计划》《目标客户清单与分工》《联合方案》《活动/拜访记录》《成交分配表》。 |
| **收费方式** | 项目服务费、分成、或各自承担成本；分成比例逐案商议，CEO 审批；不写死。 |
| **交易触发条件** | 项目费用按阶段；分成按成交/回款；具体触发写入联合协议。 |
| **双方责任** | 明确「谁开发、谁报价、谁签约、谁交付、谁收款」；客户归属以登记为准；不得私下截单。 |
| **佣金结算** | 按约定周期结算；涉及跨境支付须确认税务与外汇合规（律师/财务确认）。 |
| **客户保护** | 联合登记客户名单；保护期内归属清晰；一方退出时存量商机按协议处理。 |
| **非独家/独家** | 通常非独家；特定活动/区域可短期独家。 |
| **利益冲突** | 伙伴若同时代理其他算力供给，须披露；不得利用联合项目为竞品导流。 |
| **风险** | 分工不清、客户归属争议、伙伴交付能力不足、品牌混用。 |
| **适用场景** | 伙伴有本地客户/渠道但缺中国供给；我方有供给但缺当地落地能力；双方愿意共同投入。 |
| **不适用场景** | 伙伴只想拿名单不投入；伙伴要求我方承担全部成本；客户归属无法书面约定。 |

**关键条款**：联合体定位（非合伙、非代理）、分工与客户归属、费用与分成、品牌使用、保密、退出与存量商机。正式文本须律师起草。

## 5. 模式 E：长期算力采购管理（Managed Compute Procurement）

> 定位：客户买的是「持续有人替他管算力采购」——多供应商、多区域、持续扩容时的采购运营能力。

| 项目 | 设计 |
|------|------|
| **付款方** | 客户（需求方）。 |
| **服务内容** | 年度算力采购策略；供应商池管理；季度询价与比价；合同与 SLA 跟踪；交付验收协调；成本优化；风险与合规提示（非法律意见）。 |
| **交付物** | 《年度采购策略》《供应商池与评分》《季度比价报告》《交付与 SLA 跟踪表》《成本优化建议》《年度复盘》。 |
| **收费方式** | 年度/季度管理费（固定）＋绩效费（按节省成本或成交额，逐案商议）；不写死比例。 |
| **交易触发条件** | 管理费按周期；绩效费按约定指标（如实际节省额、达成交付）确认后结算。 |
| **双方责任** | 我方：持续服务、独立比对、披露冲突；客户：授权范围、及时决策、按约付费。 |
| **佣金结算** | 按季度/年度开票；绩效费需双方确认计算口径；币种与汇率写入协议。 |
| **客户保护** | 客户数据与采购策略保密；不向供应商泄露客户底价；不利用客户信息自营。 |
| **非独家/独家** | 默认非独家；客户可要求品类独家（须对价与 CEO 批准）。 |
| **利益冲突** | 若供应商向我方付费（模式 B/C），必须向客户披露收费来源；客户可要求「只收客户方费用」的干净模式。 |
| **风险** | 客户采购量不足、绩效指标争议、长期合同绑定过重、供应商关系被替代。 |
| **适用场景** | 客户多区域/多供应商、持续扩容、内部采购团队薄弱；年采购额达到可覆盖服务成本。 |
| **不适用场景** | 一次性小额采购；客户要求我方承担价格风险；客户要求资金托管。 |

**关键条款**：服务范围与排除项、SLA、费用与绩效计算、数据与保密、利益冲突、终止与交接。正式文本须律师起草。

## 6. 模式选择决策树

```
Q1. 现在有「可识别的单笔商机」吗？
 ├─ 有 → Q2. 供应商愿意签介绍协议并接受成功付费方向吗？
 │        ├─ 愿意 → 模式 C（单笔成功介绍）
 │        └─ 不愿意 → 暂停；或改模式 A（若客户愿意付顾问费）
 └─ 没有 → Q3. 付费方主要是谁？
          ├─ 供应商想持续开发海外 → 模式 B（非独家渠道）
          ├─ 客户想持续管理采购 → Q4. 是否长期、多供应商？
          │                        ├─ 是 → 模式 E（长期采购管理）
          │                        └─ 否 → 模式 A（单项目顾问）
          └─ 有本地伙伴共同拓客 → 模式 D（联合市场拓展）

Q5. 同一交易是否可能双边收费？
 ├─ 是 → 必须事前书面披露 + CEO 批准；否则只向一方收费
 └─ 否 → 按 Q1–Q4 单一模式执行
```

## 7. 组合使用规则

| 组合 | 是否允许 | 规则 |
|------|----------|------|
| A + E | ✅ | 先单项目顾问，转长期采购管理；同一交付不得重复计费。 |
| B + C | ✅ | 渠道合作下的具体商机走 C 的登记与结算；成功费不重复收。 |
| C + D | ✅ | 联合拓展产生的商机按 D 的分成 + C 的介绍费规则，须事先写清归属。 |
| A + B（同一客户/供应商同一交易） | ⚠️ 仅披露后 | 必须书面披露双边收费与角色，取得双方同意，CEO 批准；不得同时代表双方谈判。 |
| B + E（同一交易） | ⚠️ 仅披露后 | 同上；客户侧须知道供应商向我方付费。 |
| C + C（同一商机多供应商） | ❌ | 同一商机只向一家供应商登记介绍，避免重复兜售。 |
| 任何模式 + 资金托管 | ❌ | 红线：不托管客户采购资金。 |
| 任何模式 + 需方加价 | ❌ | 红线：不在需方价格上加价。 |

## 8. 利益冲突与披露总则

1. **先披露、后收费**：任何双边收费、任何同时服务供需双方的情形，必须在收费前书面披露。
2. **披露内容**：谁付费、费用类型、计费基础、是否影响推荐排序。
3. **不得隐藏**：不得以「免费服务」掩盖后续收费，不得用关联方代收。
4. **客户选择权**：客户可要求「只向客户收费、不向供应商收费」的干净模式，我方应能提供。
5. **记录**：披露文件、对方确认、CEO 审批记录存入 `commercial_opportunities` 与 `audit_logs`。

## 9. 红线与禁止事项

- ❌ 自营 GPU 机房、自购 GPU 库存、Token 工厂/API 零售。
- ❌ 未获授权的芯片/算力交易、规避出口管制。
- ❌ 客户资金托管、需方价格加价。
- ❌ 未披露的双边收费、同一交易重复收费。
- ❌ 承诺合规、承诺交付、承诺成交、虚构案例。
- ❌ 未签协议先介绍、未登记先介绍。
- ✅ 任何模式下，合同均由供需双方直接签署；我方不代签、不代收、不承担交付责任。
